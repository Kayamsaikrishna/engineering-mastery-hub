🚀 What is SQL?

Definition

SQL (Structured Query Language) is the standard language for managing and manipulating relational databases. It's used to store, retrieve, update, and delete data from databases.

🔑 Critical Insight: SQL is DECLARATIVE - you tell it WHAT you want, not HOW to get it. The database figures out the most efficient way.

Why Learn SQL?

  • Universal: Used by 90%+ of companies - MySQL, PostgreSQL, Oracle, SQL Server
  • Essential Skill: Required for data analysis, backend development, data science
  • Interview Must-Have: Common in technical interviews
  • Real-World Power: Query millions of records in seconds
  • Career Growth: Database skills = higher salary potential
💡 Memory Trick: Database = Digital Filing Cabinet
  • Database = The entire filing cabinet
  • Table = A drawer in the cabinet
  • Row = A single file/document
  • Column = Information field on the document

📚 SQL Basics

1. Database & Table Operations

SQL - Create Database & Table
-- Create a new database CREATE DATABASE company_db; -- Use the database USE company_db; -- Create a table CREATE TABLE employees ( id INT PRIMARY KEY AUTO_INCREMENT, name VARCHAR(100) NOT NULL, email VARCHAR(100) UNIQUE, department VARCHAR(50), salary DECIMAL(10, 2), hire_date DATE, is_active BOOLEAN DEFAULT TRUE ); -- View table structure DESCRIBE employees; -- or SHOW COLUMNS FROM employees;

Common Data Types:

  • INT - Integer numbers
  • VARCHAR(n) - Variable-length string (max n characters)
  • TEXT - Long text
  • DECIMAL(p,s) - Decimal numbers (precision, scale)
  • DATE - Date (YYYY-MM-DD)
  • DATETIME - Date and time
  • BOOLEAN - True/False

2. INSERT - Adding Data

SQL - INSERT Statements
-- Insert single row INSERT INTO employees (name, email, department, salary, hire_date) VALUES ('Alice Johnson', 'alice@company.com', 'Engineering', 85000, '2020-01-15'); -- Insert multiple rows INSERT INTO employees (name, email, department, salary, hire_date) VALUES ('Bob Smith', 'bob@company.com', 'Sales', 65000, '2019-06-10'), ('Carol White', 'carol@company.com', 'Engineering', 90000, '2018-03-22'), ('David Lee', 'david@company.com', 'Marketing', 70000, '2021-09-01'); -- Insert with selected columns (others will be NULL or default) INSERT INTO employees (name, department) VALUES ('Eve Brown', 'HR');

3. SELECT - Retrieving Data

SQL - SELECT Queries
-- Select all columns SELECT * FROM employees; -- Select specific columns SELECT name, department, salary FROM employees; -- Select with alias (rename columns in output) SELECT name AS employee_name, salary AS annual_salary, department AS dept FROM employees; -- Select distinct values (no duplicates) SELECT DISTINCT department FROM employees; -- Count rows SELECT COUNT(*) FROM employees; SELECT COUNT(*) AS total_employees FROM employees;

4. WHERE - Filtering Data

SQL - WHERE Clause
-- Basic filtering SELECT * FROM employees WHERE department = 'Engineering'; SELECT * FROM employees WHERE salary > 70000; -- Multiple conditions (AND) SELECT * FROM employees WHERE department = 'Engineering' AND salary > 80000; -- Multiple conditions (OR) SELECT * FROM employees WHERE department = 'Engineering' OR department = 'Sales'; -- NOT operator SELECT * FROM employees WHERE NOT department = 'Engineering'; -- IN operator (multiple values) SELECT * FROM employees WHERE department IN ('Engineering', 'Sales', 'Marketing'); -- BETWEEN operator SELECT * FROM employees WHERE salary BETWEEN 60000 AND 80000; -- LIKE operator (pattern matching) SELECT * FROM employees WHERE name LIKE 'A%'; -- Names starting with A SELECT * FROM employees WHERE email LIKE '%@company.com'; -- Emails ending with @company.com -- IS NULL / IS NOT NULL SELECT * FROM employees WHERE email IS NULL; SELECT * FROM employees WHERE email IS NOT NULL;
⚠️ Wildcards with LIKE:
  • % - Matches any sequence of characters
  • _ - Matches exactly one character
  • 'A%' - Starts with A
  • '%son' - Ends with son
  • '%data%' - Contains data
  • '_ob' - Three letters ending with ob (Bob, Rob)

5. ORDER BY - Sorting Results

SQL - ORDER BY
-- Sort ascending (default) SELECT * FROM employees ORDER BY salary; -- Sort descending SELECT * FROM employees ORDER BY salary DESC; -- Sort by multiple columns SELECT * FROM employees ORDER BY department ASC, salary DESC; -- Sort with column alias SELECT name, salary * 12 AS yearly_salary FROM employees ORDER BY yearly_salary DESC;

6. LIMIT - Restricting Results

SQL - LIMIT
-- Get first 5 rows SELECT * FROM employees LIMIT 5; -- Get top 3 highest paid employees SELECT name, salary FROM employees ORDER BY salary DESC LIMIT 3; -- Pagination: Skip first 10, get next 5 SELECT * FROM employees LIMIT 5 OFFSET 10; -- or SELECT * FROM employees LIMIT 10, 5; -- MySQL syntax: offset, count

⚙️ Query Operations

1. UPDATE - Modifying Data

SQL - UPDATE Statements
-- Update single column UPDATE employees SET salary = 95000 WHERE id = 1; -- Update multiple columns UPDATE employees SET salary = 72000, department = 'Sales' WHERE name = 'David Lee'; -- Update with calculation UPDATE employees SET salary = salary * 1.10 -- 10% raise WHERE department = 'Engineering'; -- Update all rows (BE CAREFUL!) UPDATE employees SET is_active = TRUE;
⚠️ CRITICAL WARNING: Always use WHERE with UPDATE! Without it, ALL rows will be updated. Test with SELECT first!

2. DELETE - Removing Data

SQL - DELETE Statements
-- Delete specific rows DELETE FROM employees WHERE id = 5; DELETE FROM employees WHERE department = 'Marketing' AND salary < 50000; -- Delete all rows (BE VERY CAREFUL!) DELETE FROM employees; -- Safer deletion with LIMIT DELETE FROM employees WHERE department = 'Sales' LIMIT 1; -- Delete only first matching row
⚠️ DELETE vs TRUNCATE vs DROP:
  • DELETE - Removes rows, can use WHERE, slower, can rollback
  • TRUNCATE - Removes all rows, faster, resets auto-increment, cannot rollback
  • DROP - Deletes entire table structure and data

3. Aggregate Functions

SQL - Aggregate Functions
-- COUNT - Count rows SELECT COUNT(*) AS total_employees FROM employees; SELECT COUNT(DISTINCT department) AS num_departments FROM employees; -- SUM - Sum of values SELECT SUM(salary) AS total_payroll FROM employees; -- AVG - Average value SELECT AVG(salary) AS average_salary FROM employees; -- MIN - Minimum value SELECT MIN(salary) AS lowest_salary FROM employees; -- MAX - Maximum value SELECT MAX(salary) AS highest_salary FROM employees; -- Multiple aggregates SELECT COUNT(*) AS total_count, AVG(salary) AS avg_salary, MIN(salary) AS min_salary, MAX(salary) AS max_salary, SUM(salary) AS total_salary FROM employees;

4. GROUP BY - Grouping Data

SQL - GROUP BY
-- Count employees per department SELECT department, COUNT(*) AS employee_count FROM employees GROUP BY department; -- Average salary per department SELECT department, AVG(salary) AS avg_salary FROM employees GROUP BY department; -- Multiple columns grouping SELECT department, YEAR(hire_date) AS hire_year, COUNT(*) AS count FROM employees GROUP BY department, YEAR(hire_date); -- With ORDER BY SELECT department, AVG(salary) AS avg_salary FROM employees GROUP BY department ORDER BY avg_salary DESC;
💡 GROUP BY Rule: Every column in SELECT must either be:
1. In the GROUP BY clause, OR
2. Inside an aggregate function (COUNT, SUM, AVG, etc.)

5. HAVING - Filtering Groups

SQL - HAVING Clause
-- WHERE filters rows, HAVING filters groups -- Departments with more than 2 employees SELECT department, COUNT(*) AS employee_count FROM employees GROUP BY department HAVING COUNT(*) > 2; -- Departments with average salary > 75000 SELECT department, AVG(salary) AS avg_salary FROM employees GROUP BY department HAVING AVG(salary) > 75000; -- Combine WHERE and HAVING SELECT department, AVG(salary) AS avg_salary FROM employees WHERE hire_date >= '2019-01-01' -- Filter individual rows GROUP BY department HAVING AVG(salary) > 70000; -- Filter groups
WHERE vs HAVING:
  • WHERE - Filters rows BEFORE grouping
  • HAVING - Filters groups AFTER grouping
  • WHERE - Cannot use aggregate functions
  • HAVING - Can use aggregate functions

6. String Functions

SQL - String Functions
-- CONCAT - Combine strings SELECT CONCAT(name, ' - ', department) AS employee_info FROM employees; -- UPPER / LOWER - Change case SELECT UPPER(name) AS uppercase_name FROM employees; SELECT LOWER(email) AS lowercase_email FROM employees; -- LENGTH - String length SELECT name, LENGTH(name) AS name_length FROM employees; -- SUBSTRING - Extract part of string SELECT name, SUBSTRING(name, 1, 3) AS first_three FROM employees; -- TRIM - Remove spaces SELECT TRIM(' hello ') AS trimmed; -- REPLACE - Replace text SELECT name, REPLACE(name, 'Smith', 'Jones') AS modified FROM employees;

7. Date Functions

SQL - Date Functions
-- Current date and time SELECT NOW(); -- Current datetime SELECT CURDATE(); -- Current date SELECT CURTIME(); -- Current time -- Extract parts of date SELECT hire_date, YEAR(hire_date) AS hire_year, MONTH(hire_date) AS hire_month, DAY(hire_date) AS hire_day FROM employees; -- Date calculations SELECT name, hire_date, DATEDIFF(CURDATE(), hire_date) AS days_employed, DATEDIFF(CURDATE(), hire_date) / 365 AS years_employed FROM employees; -- Add/subtract dates SELECT DATE_ADD(CURDATE(), INTERVAL 30 DAY) AS thirty_days_later; SELECT DATE_SUB(CURDATE(), INTERVAL 1 YEAR) AS one_year_ago; -- Format dates SELECT DATE_FORMAT(hire_date, '%M %d, %Y') AS formatted_date FROM employees;

1. INNER JOIN

INNER JOIN returns only rows where there is a match in BOTH tables.

SQL - INNER JOIN
-- Basic INNER JOIN SELECT employees.name, departments.dept_name FROM employees INNER JOIN departments ON employees.dept_id = departments.dept_id; -- Using table aliases (cleaner) SELECT e.name, d.dept_name FROM employees e INNER JOIN departments d ON e.dept_id = d.dept_id; -- Result: Only Alice, Bob, Carol (David has no department match)

2. LEFT JOIN (LEFT OUTER JOIN)

LEFT JOIN returns ALL rows from the left table, and matching rows from the right table. NULL for non-matches.

SQL - LEFT JOIN
-- LEFT JOIN SELECT e.name, d.dept_name FROM employees e LEFT JOIN departments d ON e.dept_id = d.dept_id; -- Result: Alice, Bob, Carol with departments + David with NULL department -- Find employees with no department SELECT e.name FROM employees e LEFT JOIN departments d ON e.dept_id = d.dept_id WHERE d.dept_id IS NULL;

3. RIGHT JOIN (RIGHT OUTER JOIN)

RIGHT JOIN returns ALL rows from the right table, and matching rows from the left table. NULL for non-matches.

SQL - RIGHT JOIN
-- RIGHT JOIN SELECT e.name, d.dept_name FROM employees e RIGHT JOIN departments d ON e.dept_id = d.dept_id; -- Result: Alice, Bob, Carol + Marketing department with NULL employee -- Find departments with no employees SELECT d.dept_name FROM employees e RIGHT JOIN departments d ON e.dept_id = d.dept_id WHERE e.id IS NULL;

4. FULL OUTER JOIN

FULL OUTER JOIN returns ALL rows from both tables, with NULLs where there's no match. (Not directly supported in MySQL, use UNION)

SQL - FULL OUTER JOIN (MySQL Workaround)
-- Simulate FULL OUTER JOIN in MySQL SELECT e.name, d.dept_name FROM employees e LEFT JOIN departments d ON e.dept_id = d.dept_id UNION SELECT e.name, d.dept_name FROM employees e RIGHT JOIN departments d ON e.dept_id = d.dept_id;

5. CROSS JOIN

CROSS JOIN returns the Cartesian product - every combination of rows from both tables.

SQL - CROSS JOIN
-- CROSS JOIN SELECT e.name, d.dept_name FROM employees e CROSS JOIN departments d; -- Result: 4 employees × 3 departments = 12 rows

6. SELF JOIN

SELF JOIN joins a table to itself, useful for hierarchical data.

SQL - SELF JOIN
-- Example: employees with manager_id column -- Find employee and their manager name SELECT e1.name AS employee, e2.name AS manager FROM employees e1 LEFT JOIN employees e2 ON e1.manager_id = e2.id;

7. Multiple JOINs

SQL - Multiple JOINs
-- Join three tables: employees, departments, projects SELECT e.name AS employee_name, d.dept_name, p.project_name FROM employees e INNER JOIN departments d ON e.dept_id = d.dept_id INNER JOIN projects p ON e.id = p.employee_id; -- With WHERE clause SELECT e.name, d.dept_name, p.project_name FROM employees e INNER JOIN departments d ON e.dept_id = d.dept_id INNER JOIN projects p ON e.id = p.employee_id WHERE d.dept_name = 'Engineering' ORDER BY e.name;
💡 JOIN Memory Trick:
  • INNER JOIN = "Only matches" - like intersection ∩
  • LEFT JOIN = "Everything from left table"
  • RIGHT JOIN = "Everything from right table"
  • FULL OUTER = "Everything from both" - like union ∪

🎓 Advanced Concepts

1. Subqueries (Nested Queries)

SQL - Subqueries
-- Subquery in WHERE clause -- Find employees with salary above average SELECT name, salary FROM employees WHERE salary > (SELECT AVG(salary) FROM employees); -- Subquery in FROM clause SELECT dept, avg_sal FROM ( SELECT department AS dept, AVG(salary) AS avg_sal FROM employees GROUP BY department ) AS dept_stats WHERE avg_sal > 70000; -- Subquery with IN -- Find employees in departments with more than 5 people SELECT name, department FROM employees WHERE department IN ( SELECT department FROM employees GROUP BY department HAVING COUNT(*) > 5 ); -- Correlated subquery (references outer query) SELECT name, salary, department FROM employees e1 WHERE salary > ( SELECT AVG(salary) FROM employees e2 WHERE e2.department = e1.department );

2. UNION & UNION ALL

UNION combines results from multiple SELECT statements, removing duplicates.

UNION ALL includes duplicates.

SQL - UNION
-- UNION (removes duplicates) SELECT name FROM employees UNION SELECT name FROM contractors; -- UNION ALL (keeps duplicates, faster) SELECT name FROM employees UNION ALL SELECT name FROM contractors; -- Must have same number of columns SELECT name, 'Employee' AS type FROM employees UNION SELECT name, 'Contractor' AS type FROM contractors ORDER BY name;

3. CASE Statements (Conditional Logic)

SQL - CASE Statements
-- Simple CASE SELECT name, salary, CASE WHEN salary < 60000 THEN 'Low' WHEN salary BETWEEN 60000 AND 80000 THEN 'Medium' WHEN salary > 80000 THEN 'High' ELSE 'Unknown' END AS salary_category FROM employees; -- CASE in WHERE clause SELECT name, department FROM employees WHERE CASE WHEN department = 'Engineering' THEN salary > 80000 WHEN department = 'Sales' THEN salary > 60000 ELSE salary > 50000 END; -- CASE for custom sorting SELECT name, department FROM employees ORDER BY CASE department WHEN 'Engineering' THEN 1 WHEN 'Sales' THEN 2 WHEN 'Marketing' THEN 3 ELSE 4 END;

4. Window Functions (Analytic Functions)

Window Functions perform calculations across a set of rows related to the current row, without grouping.

SQL - Window Functions
-- ROW_NUMBER - Assign unique row numbers SELECT name, department, salary, ROW_NUMBER() OVER (ORDER BY salary DESC) AS salary_rank FROM employees; -- RANK - Ranking with gaps for ties SELECT name, department, salary, RANK() OVER (ORDER BY salary DESC) AS rank FROM employees; -- DENSE_RANK - Ranking without gaps SELECT name, salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rank FROM employees; -- PARTITION BY - Rank within groups SELECT name, department, salary, RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS dept_rank FROM employees; -- Running totals SELECT name, salary, SUM(salary) OVER (ORDER BY hire_date) AS running_total FROM employees; -- Moving average SELECT name, salary, AVG(salary) OVER ( ORDER BY hire_date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW ) AS moving_avg FROM employees;

5. Common Table Expressions (CTEs)

CTE (WITH clause) creates a temporary named result set that you can reference within a SELECT, INSERT, UPDATE, or DELETE statement.

SQL - CTEs
-- Simple CTE WITH high_earners AS ( SELECT name, salary, department FROM employees WHERE salary > 80000 ) SELECT department, COUNT(*) AS count FROM high_earners GROUP BY department; -- Multiple CTEs WITH engineering_emp AS ( SELECT * FROM employees WHERE department = 'Engineering' ), sales_emp AS ( SELECT * FROM employees WHERE department = 'Sales' ) SELECT 'Engineering' AS dept, COUNT(*) AS count FROM engineering_emp UNION ALL SELECT 'Sales' AS dept, COUNT(*) AS count FROM sales_emp; -- Recursive CTE (for hierarchical data) WITH RECURSIVE employee_hierarchy AS ( -- Base case: top-level employees SELECT id, name, manager_id, 1 AS level FROM employees WHERE manager_id IS NULL UNION ALL -- Recursive case: employees with managers SELECT e.id, e.name, e.manager_id, eh.level + 1 FROM employees e INNER JOIN employee_hierarchy eh ON e.manager_id = eh.id ) SELECT * FROM employee_hierarchy ORDER BY level, name;

6. Indexes & Performance

Indexes speed up data retrieval but slow down INSERT/UPDATE/DELETE operations.

SQL - Indexes
-- Create index CREATE INDEX idx_department ON employees(department); -- Create unique index CREATE UNIQUE INDEX idx_email ON employees(email); -- Composite index (multiple columns) CREATE INDEX idx_dept_salary ON employees(department, salary); -- View indexes SHOW INDEX FROM employees; -- Drop index DROP INDEX idx_department ON employees; -- Primary key automatically creates index ALTER TABLE employees ADD PRIMARY KEY (id); -- Foreign key ALTER TABLE employees ADD FOREIGN KEY (dept_id) REFERENCES departments(dept_id);

7. Transactions & ACID Properties

SQL - Transactions
-- Start transaction START TRANSACTION; -- or BEGIN; -- Execute multiple operations UPDATE accounts SET balance = balance - 100 WHERE id = 1; UPDATE accounts SET balance = balance + 100 WHERE id = 2; -- If everything is successful, commit COMMIT; -- If there's an error, rollback ROLLBACK; -- Example with error handling START TRANSACTION; UPDATE employees SET salary = salary * 1.1 WHERE department = 'Engineering'; -- Check if update was successful -- If not, ROLLBACK; otherwise COMMIT; COMMIT;
ACID Properties:
  • Atomicity - All or nothing (complete or rollback)
  • Consistency - Data integrity maintained
  • Isolation - Concurrent transactions don't interfere
  • Durability - Committed data persists

8. Views

SQL - Views
-- Create view (virtual table) CREATE VIEW engineering_employees AS SELECT id, name, salary, hire_date FROM employees WHERE department = 'Engineering'; -- Query the view like a table SELECT * FROM engineering_employees WHERE salary > 80000; -- Create or replace view CREATE OR REPLACE VIEW high_earners AS SELECT name, department, salary FROM employees WHERE salary > 75000; -- Drop view DROP VIEW engineering_employees;

Problem 1: Find Second Highest Salary
SQL Solution
-- Method 1: Using LIMIT with OFFSET SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 1 OFFSET 1; -- Method 2: Using subquery SELECT MAX(salary) AS second_highest FROM employees WHERE salary < (SELECT MAX(salary) FROM employees); -- Method 3: Using window function WITH ranked_salaries AS ( SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rank FROM employees ) SELECT salary FROM ranked_salaries WHERE rank = 2;
Problem 2: Find Duplicate Emails
SQL Solution
-- Find emails that appear more than once SELECT email, COUNT(*) AS count FROM employees GROUP BY email HAVING COUNT(*) > 1; -- Get all records with duplicate emails SELECT * FROM employees WHERE email IN ( SELECT email FROM employees GROUP BY email HAVING COUNT(*) > 1 );
Problem 3: Customers Who Never Ordered
SQL Solution
-- Method 1: Using LEFT JOIN SELECT c.name FROM customers c LEFT JOIN orders o ON c.customer_id = o.customer_id WHERE o.order_id IS NULL; -- Method 2: Using NOT IN SELECT name FROM customers WHERE customer_id NOT IN ( SELECT DISTINCT customer_id FROM orders ); -- Method 3: Using NOT EXISTS SELECT name FROM customers c WHERE NOT EXISTS ( SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id );
Problem 4: Nth Highest Value
SQL Solution
-- Find Nth highest salary (N = 3) -- Method 1: Using LIMIT SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 1 OFFSET 2; -- N-1 -- Method 2: Function approach CREATE FUNCTION getNthHighestSalary(N INT) RETURNS INT BEGIN DECLARE M INT; SET M = N - 1; RETURN ( SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 1 OFFSET M ); END;
Problem 5: Department with Highest Average Salary
SQL Solution
SELECT department, AVG(salary) AS avg_salary FROM employees GROUP BY department ORDER BY avg_salary DESC LIMIT 1; -- Alternative: Using subquery SELECT department, AVG(salary) AS avg_salary FROM employees GROUP BY department HAVING AVG(salary) = ( SELECT MAX(avg_sal) FROM ( SELECT AVG(salary) AS avg_sal FROM employees GROUP BY department ) AS dept_averages );
Problem 6: Consecutive Numbers
SQL Solution
-- Find numbers that appear at least 3 times consecutively -- Assuming a Logs table with id and num columns SELECT DISTINCT l1.num AS ConsecutiveNums FROM Logs l1 JOIN Logs l2 ON l1.id = l2.id - 1 JOIN Logs l3 ON l2.id = l3.id - 1 WHERE l1.num = l2.num AND l2.num = l3.num;

🎯 Key SQL Concepts to Master

The 10 SQL Commandments:
  1. Always use WHERE with UPDATE/DELETE
  2. Test with SELECT before UPDATE/DELETE
  3. Use LIMIT when testing queries on large tables
  4. Index frequently queried columns for performance
  5. Use JOINs wisely - understand LEFT vs INNER
  6. GROUP BY all non-aggregated columns in SELECT
  7. HAVING filters groups, WHERE filters rows
  8. Use aliases for readability
  9. Avoid SELECT * in production code
  10. Use transactions for related operations

📊 SQL Query Order of Execution

Order Clause Purpose
1 FROM Choose the table(s)
2 JOIN Combine tables
3 WHERE Filter rows
4 GROUP BY Group rows
5 HAVING Filter groups
6 SELECT Choose columns
7 DISTINCT Remove duplicates
8 ORDER BY Sort results
9 LIMIT Restrict number of rows

💡 SQL Best Practices

Performance Tips:
  • Use EXISTS instead of IN for large subqueries
  • Use UNION ALL instead of UNION when duplicates don't matter
  • Index columns used in WHERE, JOIN, and ORDER BY
  • Avoid functions on indexed columns in WHERE (breaks index)
  • Use LIMIT for pagination instead of loading all data
  • Use EXPLAIN to analyze query performance
